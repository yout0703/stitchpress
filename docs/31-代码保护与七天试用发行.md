# 代码保护与七天试用发行

2026-11-13。`0.1.0.dev19` 是无期限的内部验证基线，新开发版本为 `0.1.0.dev20`，正在加入离线授权与代码保护并单独验收。用户本次要求覆盖此前“首版免费、无授权限制”的决定；不得把旧 dev19 包交付为七天试用版。

## 已确认与实施口径

- 已确认：客户交付为试用版；有效期七天；到期锁定软件业务功能；需要考虑代码混淆与保护。
- 已确认：用户改选完全离线机器码签发，服务端激活后续再考虑；没有激活网络请求、定期联网或远程撤销。
- 当前实现口径：客户导出机器码，发行方收到后签发绑定设备的授权文件；从签发时间起连续 168 小时，UTC 保存，界面显示当地准确到期时间。离线无法可靠核实可重置的“首次启动时间”，因此不从首次运行自动开始计时。下载安装、构建和导出机器码均不开始试用。
- 升级、普通重装、重新导入同一授权均不能改变文件中签名的原到期时间；新签授权必须由发行方明确操作。未来正式/长期授权尚未实现，不把重新签发七天试用当作长期正式授权。

## 到期锁定的产品行为

到期后停止导入、编辑、制版、生成预览、商品制作及各类业务导出；仅保留授权状态、激活/导入授权、帮助、诊断和退出入口。客户原有工程及已经导出的文件继续保留，不能加密扣留、删除或改坏。

长开窗口不能绕过到期：定时更新授权状态，所有业务入口以及工作进程启动和发布结果前均检查。到期时保护当前未保存修改，写入可恢复草稿后锁定；保存失败时明确提示并保留恢复所需数据，不静默丢弃。业务导出在到期后不发布最终结果，使用安全取消与临时目录清理；原已存在的成品不得删除。恢复草稿属于数据保护，不开放新的制版能力。

试用期内显示剩余时间和准确到期时间。过期、未激活、设备不匹配、时间异常、签名损坏、安全存储不可用分别显示原因和恢复路径；不依赖服务可用性。

## 授权结构与防绕过边界

授权与作品格式分离。应用层集中提供授权决策；GUI、CLI、后台工作进程和最终发布共用约束，不能只禁用几个按钮。核心图纸/几何模块继续不依赖 Qt 或网络。

发行端签名，客户端只含校验公钥；发行私钥不得进入客户端、仓库、作品包、普通 JSON 或日志。设备标识采用必要且明确说明的最小范围，不采集个人文件。诊断脱敏；授权状态不随作品复制。

后续联网方案可由服务端保存首次激活及到期时间、使用一次性试用凭证、对设备发短期签名凭据；不属于本轮实施，不为此部署服务或产生服务费用。

完全离线方案使用绑定设备、明确起止时间的签名授权文件，记录本地最大已见时间并检测回拨；不把“第一次启动写一个日期”当可靠授权。无可信服务器或硬件计时锚时，管理员删除全部记录、虚拟机快照/克隆、系统重装及补丁破解不能被可靠阻止，必须如实告知。机器码和本地加密不等同不可绕过。

所有客户端保护只能提高逆向和绕过成本，不能承诺绝对无法破解。旧版无期限开发包不会因发布新试用包自行失效，不能把新策略当作对旧包的远程撤销。

## 代码保护方案

当前 `tools/build_desktop.py` 默认使用 PyInstaller，尚无专门保护步骤。PyInstaller 的打包代码可被提取分析，不能把 EXE、压缩、改名或单文件包装称为混淆保护。[官方说明](https://github.com/pyinstaller/pyinstaller/blob/develop/doc/operating-mode.rst#hiding-the-source-code)

建议先做两条隔离构建验证，再确定客户发行链：

1. 保留已验证的 PyInstaller 外壳，采用 Cython 将授权校验和关键自有业务模块编译为原生扩展；检查对应模块不以 `.py` / `.pyc` 形式重复随包发布。动态导入、资源定位和子进程均需实际回归。[PyInstaller 对此路径的说明](https://github.com/pyinstaller/pyinstaller/blob/develop/doc/operating-mode.rst#hiding-the-source-code)
2. 使用已有 Nuitka 构建入口做完整原生编译候选；先重新验证历史 Mac 中文路径问题、Windows 中文路径、PySide6 与后台子进程，再决定是否替换默认构建器。常量/资源保护属于不同能力，普通编译不能据此宣称所有数据隐藏；商业增强不得未经用户决定采购。[Nuitka 官方保护能力说明](https://nuitka.net/doc/commercial.html)

混淆仅作用于发行产物，保留可维护源码、依赖声明、第三方许可和内部排错资料。代码签名负责来源及完整性，不能代替混淆或试用授权。构建清单、受保护模块清单与实际包内容需要核对；保护前后确定性图纸结果一致。

内部开发和客户试用使用独立构建配置及文件名；客户包不包含开发绕过入口、测试签名密钥或可通过环境变量/CLI 开关解除试用的选项。测试凭证不能在生产信任链生效。

## 发行方操作

当前发行密钥标识为 `stitchpress-offline-2026-v1`。其私钥已在开发Mac系统钥匙串生成，未导出为文件；仓库 `release/trial-public-keys.json` 只有公钥。不得将钥匙串私钥转存至CI、普通配置或客户包。开发机重装/丢失钥匙串之前需由发行方通过安全的系统凭据备份流程保全；丢失后不能凭公钥恢复私钥。

客户发来机器码后，在本仓库根目录运行（路径替换为本次客户文件，不向客户交付发行脚本）：

```sh
uv run --all-groups python tools/issue_trial.py issue \
  --key-id stitchpress-offline-2026-v1 \
  --request /绝对路径/客户机器码.json \
  --customer 客户名称 \
  --output /绝对路径/客户七天试用.spl-license
```

此操作即时签发七天授权，因此应在客户准备开始试用时执行；不同客户或新签发使用新文件名，工具拒绝覆盖已有文件。授权文件可发给对应客户，发行私钥不可发送。本轮只签发内部Mac测试设备的授权，没有替客户消耗试用时间。

受保护试用构建：

```sh
uv run --all-groups python tools/build_desktop.py \
  --edition trial --protect --public-keys release/trial-public-keys.json
```

分别在Windows/macOS原生环境运行。构建器拒绝没有公钥或未启用保护的trial构建；输出独立于普通开发包。构建自动审核受保护模块不存在PYZ字节码回退且对应原生扩展齐全。
