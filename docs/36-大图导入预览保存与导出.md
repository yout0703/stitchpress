# dev25 大图支持与验收

2026-11-15。客户只反馈“打开超限”，尚未收到其原始文件和提示原文。本次以自有压力输入覆盖旧容量边界，不声称已复现客户原件，也不将未知针法当作全针导入。

## 实现

- XSD 解码改为紧凑 uint32 数组与逐行标签，避免每格临时 Python 整数列表；OXS 两次流式解析，逐针释放 XML 节点，位图检测重复坐标。OXS 导出逐行序列化，避免构造完整 XML 对象树。
- 大图纸/作品在可取消的独立工作进程中解析和校验；成功后采用快照。失败、取消及打开期间源文件发生变化都不替换原草稿。现有旧格式仍按原迁移规则另存。
- 编辑台全景最多 2048px，放大只绘制视口针格。生产/整张查图概览按真实输出坐标采样，使用不超过 8MiB 的 CMYK 源条带；概览不会成为生产母版。展示点图最多4096px并明确记录仅供展示。
- 生产和整张阅读 TIFF 均分条编码，反读所有条带 SHA、每格像素、针数、DPI、ICC、容器类型。阅读分页仍逐页渲染。输出时不缩小针格母版或更改格距。
- 大原图预览先缩略后颜色归一化，JPEG 使用解码器缩采样。原始资源保留；像素哈希和 RGB 输出反读按条带计算，减少整图临时数组。
- 保存只序列化一次，通过清单逐项比较和流式资源 SHA/CRC 复核，避免再解压为第二份完整作品。历史备份按块原子复制；旧版本仍保留。大针格作品即使资源文件较小也走后台保存。

## 当前边界

| 对象 | 旧值 | 新值与处理 |
|---|---|---|
| XSD/OXS | 16MiB、100万格 | 256MiB、400万格；全针语义和512色约束继续保留 |
| 原图 | 64MiB、4000万像素 | 128MiB、1亿像素；单帧、颜色管理约束保留 |
| 作品容器/解压资源合计 | 256MiB | 1GiB；清单128MiB，2048项，路径/哈希/CRC约束保留 |
| 生产 TIFF | 2.5亿像素、宽6万px | 分条输出最多10亿像素、宽10万px |
| 整张阅读 TIFF | 8000万像素整图分配 | 同上分条输出；超过5亿像素须显式确认BigTIFF |
| 阅读分页 | 主流程200页，旧导出100页 | 1000页；单页8000万像素限制保留 |

这些是当前实现的容量保护，并非所有边界组合都已实测。TIFF 实际尺寸仍受格距、DPI、标题和图例影响；不能仅按针格数量推断能否使用经典TIFF。超过预算时给出尺寸与调整方法，不静默改变输出尺寸。

## 验证方法

`tools/large_patterns.py` 生成自有 PM-v4 输入：1200×900，共108万格、72万针、2色，含17MiB合法非针法附加区，文件超过16MiB；非客户图纸，不使用参考软件内部资源。

`tools/validate_bundle_large.py` 同时用于源码和 Windows 实际 EXE：

1. 大 XSD 与大 OXS 独立导入，逐格、每色针数和线色语义相等。
2. 含270MiB自有资源及6500×6500原图的作品保存、后台重开、资源逐字节相等。
3. 生产、整张阅读、分页、效果预览；原稿、原图、生产、整张、分页、点图及自包含设置导出，逐文件反读和设置恢复。
4. 实际 Qt 编辑台打开、另存、导入、取消、视口绘制；记录事件循环心跳和最长停顿。另存独立副本，原文件SHA保持不变。
5. 450×1100格、14CT、300DPI测试真实超过2.5亿像素的生产图与超过8000万像素的整张阅读图；全条带反读。

每个工作进程记录耗时和本进程峰值常驻内存。Windows 的计数来自 GetProcessMemoryInfo，Mac 来自 getrusage；不把条带8MiB误写成整个应用仅占8MiB。主作品资源和针格仍在内存，百万格作品切入时仍可能有短暂停顿。

同一350×350、82664针 OXS 对比旧解析器（6c34955）与新解析器：tracemalloc 解析峰值约44.8MiB→2.1MiB，约下降95%；该仪器下耗时1.03s→1.75s。此比较证明内存优化，不能作为Windows端耗时结论。
