# R1 本地接续与验收

2026-11-11，开发版 0.1.0.dev2。这里只记录新增实现；完整R1状态以根目录TODO为准。本轮没有真实AI调用、Windows执行、客户外发或工厂试印。

## 可实际使用的新增流程

- **外部蓝图候选**：AI助手或母版菜单导入真实文件，记录来源及用户填写的供应商/模型；保存原字节、规范化RGBA PNG、ICC处理、尺寸和SHA。先并排比较，再人工确认采用；取消不改原图/母版。采用蓝图后保留针格原版，等待转换与重新审核。来源声明不算供应商真实调用证明。
- **局部图像返修**：用户提供同画幅、已对齐的编辑文件并明确确认对齐后，只合成针格选区对应像素，逐条带核对外区字节不变；保留编辑原件、合成版本和来源。尺寸相同不能证明内容对齐，保护区/确认留空处拒绝修改。候选不自动采用，不使用尚未接入的图像服务。
- **选区重新量化**：只量化选中的针格区，复用当前目录与固定网格；只追加必要颜色，不重编号/改写外区色板。原值、保护区、有效色数、符号容量和区域外线材身份/RGB分别检查；零变化给出说明，不伪造新修订；主体蒙版与透明留空冲突时停止。
- **针格候选比较**：当前采用版/候选的实际矩阵并排显示，列出针数、色数、变化格数和边界；接受、拒绝、关闭均保留候选与旧母版。比较由独立工作进程执行，迟到结果保留原分支，不切换当前工程；旧候选源图不符或来源记录缺失时，要求恢复原输入，不直接套用。
- **S19补丁后重转**：沿父修订链求净变化，按品牌/线号/目录修订/RGB比较。每格明确可迁移、冲突或新图已包含；尺寸改变不缩放坐标，原值不符、保护区、目录不符不能勾选。默认不迁移，用户选择后先产生另一个候选，再比较采用。列表每页2000格、跨页保留选择；单个提议最多10万处变化，超限要求拆分，不静默截断。
- **多边形蒙版**：主体有针、负空间留空、保护区支持针格顶点多边形。左键逐点，双击/右键完成，Esc取消；按精确格中心/奇偶规则填充，不平滑或自动补洞。可逐条移除标注，保存前取消不改作品。网格或源图改变不能自动套用旧蒙版，白色有针和留空继续分开。
- **本地流程看板**：已有工程/客户来图/文字三个入口，显示设计要求、蓝图、转换、数字检查、人工冻结、整包的真实状态。支持具名设备的暂停/恢复及本机接续；继续只执行下一本地操作，不调用模型、不自动采用或冻结。完整包必须匹配当前货号、尺寸、字体、映射、ICC、材料规则、文字等输入快照，演示/补件/旧配置不计整包完成。

实现入口：`core/proposals.py`、`core/blueprints.py`、`core/conversion.py`、`core/masks.py`、`app/candidates.py`、`app/blueprints.py`、`app/revisions.py`、`app/workflow*.py`。核心不导入Qt，工作进程只写自己的任务目录。

## 审核与数据升级

审核冻结现在绑定母版及源图、DesignBrief、蒙版、源ICC的实际SHA；任一内容改变需重新核对来源。正式生产和商品导出均独立验证这些关系，数字检查不替代具名人工审核。冻结前先要求当前母版数字检查，并仍需整体、两处不同局部、负空间与来源审查。

作品容器升级为**schema 2**，内层全针Design格式仍为schema 1；两者不可混为一谈。schema 1作品可以打开，保存会要求另存新副本，原文件不能原地覆盖。迁移记录包含原容器SHA、原工程身份、起止版本及旧审核需复核的说明；资源字节保留。schema 2不能在旧版程序写回，未知/未来版本明确拒绝。

```bash
uv run stitchpress inspect 旧作品.stitchpress
uv run stitchpress migrate 旧作品.stitchpress 升级副本.stitchpress
```

迁移CLI拒绝同一路径或已存在目标，输出原件/新件SHA和资源核对。界面另存还会生成独立工程身份；恢复草稿与后台输入快照同样保留完整资源。

本地发布增加排他锁。若文件已原子发布、最终执行回执写入中断，可按实际文件清单/大小/SHA恢复完成结果，保留原中断状态；文件后来变化则拒绝恢复。模拟磁盘不足、PDF失败、保存失败、发布碰撞及回执中断只说明这些边界通过，不代表所有硬件/断电情况验证完毕。

## 检查与构建

自动检查包含S19语义迁移、同RGB不同目录身份、保护区冲突、局部外区不变、蒙版冲突/取消/携带、旧版迁移、审核来源变化、整包配置失效及故障恢复。当前157项pytest、ruff检查/格式通过；最终构建和原生证据写在TODO及`reports/local/r1-revisions-final-2026-11-11/`。

原生程序检查入口（不继承开发环境的Python变量）：

```bash
uv run --all-groups python tools/build_desktop.py
uv run --all-groups python tools/smoke_bundle.py dist/macos/StitchPress.app/Contents/MacOS/StitchPress --output reports/local/本次最小检查
uv run --all-groups python tools/validate_bundle_revisions.py dist/macos/StitchPress.app/Contents/MacOS/StitchPress --output reports/local/本次修订检查
uv run --all-groups python tools/validate_bundle_extensions.py dist/macos/StitchPress.app/Contents/MacOS/StitchPress --output reports/local/本次扩展检查
```

`--internal-cli-report <回执路径> <命令…>`提供不依赖标准输出句柄的文件返回协议，为Windows无控制台构建准备；源码及Mac打包实测不代表Windows通过。

## Windows构建准备

`.github/workflows/windows-manual.yml`仅有`workflow_dispatch`：Windows x64托管环境检查、构建、中文安装路径复制后运行实际程序/工作进程，保存7天测试记录及未签名内测ZIP。只使用自有夹具，不导入客户资源、密钥或运行模型；没有push/PR自动触发，也没有执行本流程。

GitHub要求手动流程文件先存在于默认分支，才能从Actions使用Run workflow；当前只提交/推送开发分支，不为触发构建擅自合并默认分支。准备好后可经正常审阅进入默认分支，检查账户Actions额度并手动执行。配置准备不算Windows构建成功；托管runner数字检查也不替代客户屏幕缩放、鼠标交互、干净安装、目标软件和工厂实测。
